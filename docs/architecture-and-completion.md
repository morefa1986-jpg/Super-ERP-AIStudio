# معماری و وضعیت تکمیل Fathi Aqua Super ERP

## زبان و فناوری

- رابط کاربری: TypeScript و React 19
- سبک‌دهی: Tailwind CSS و CSS اختصاصی
- سرور: TypeScript، Node.js و Express
- ارتباط زنده: WebSocket
- داده محلی: LocalStorage و IndexedDB برای cache و اعتبار ورود رمزنگاری‌شده
- داده مرکزی: SQLite از طریق لایه Repository
- build: Vite و esbuild
- تست: تست‌های TypeScript مستقیم و تست production health

## منطق اصلی

1. کاربر با سرور احراز هویت می‌شود و توکن نشست دریافت می‌کند.
2. اطلاعات عملیاتی از طریق Repository خوانده و ذخیره می‌شوند.
3. در حالت قطع شبکه، تغییرات در صف محلی باقی می‌مانند و پس از اتصال همگام می‌شوند.
4. موجودی هر استخر از جمع گروه‌های ماهی محاسبه می‌شود:

   `biomassKg = count × avgWeightGrams ÷ 1000`

5. شماره چیپ‌ها نرمال‌سازی، یکتا و در کل استخرها اعتبارسنجی می‌شوند.
6. پیام‌های WebSocket فقط با هویت نشست معتبر پذیرفته می‌شوند.

## مدیریت خطا

- ورودی‌های موجودی، چیپ، جنسیت، نژاد، پورت و host اعتبارسنجی می‌شوند.
- خطاهای شبکه به حالت آفلاین هدایت می‌شوند؛ خطای احراز هویت با خطای شبکه اشتباه گرفته نمی‌شود.
- فایل‌های پشتیبان checksum و schema version دارند.
- endpointهای حساس بدون توکن معتبر پاسخ 401 دریافت می‌کنند.

## بخش‌هایی که باید در نسخه‌های بعدی تکمیل شوند

- افزودن rate limiting در endpoint ورود
- تست سرتاسری مرورگر با Playwright
- آزمون واقعی نصب و حذف روی Windows 10 و 11
- ترجمه تمام متن‌های تخصصی ماژول‌ها به resource keyهای مستقل
- تکمیل حسابداری دوبل، حقوق و دستمزد و فروش به‌عنوان ماژول‌های کامل تجاری

این موارد مانع اجرای نسخه فعلی نیستند، اما برای انتشار عمومی و فروش سازمانی باید در برنامه انتشار قرار گیرند.
